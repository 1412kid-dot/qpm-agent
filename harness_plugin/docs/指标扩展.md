# 指标与工作流扩展

Skill 是操作说明，工具是执行入口，Python校验确定能力边界。新增指标不会因写入提示词而自动拥有计算实现。

## 两类接口

`adapter`: `adapt_task(task: dict) -> dict`。只修改合法配置；沿用现有工具链。输出继续受材料、传播方向、模式、指标及插件预算限制。多阶段工作流由助手按适配结果逐轮计划和提交，仍计入轮数，不能隐藏批量求解。

`postprocess`: `analyze_result(context: dict) -> dict`。context包含contract_version、source_result_file、task、validation、cost、failures、curves、tolerances、spectral、search、metric_units。数值缺失为null，曲线点保留valid状态。不读取完整场数组，也不提供求解器对象。

返回字典只允许metrics、tables、curves、notes。metric包含name、value、unit、definition、valid、source；value是有限数或null，null不能标为valid。table包含name、columns、units和同列名的rows。curve包含name、x、y、x_unit、y_unit、definition，可指定逐点valid；无效点绘制为断点。表格每列必须说明单位；无量纲用`dimensionless`。name使用小写字母、数字、下划线或连字符，不能包含路径。

新输出保存在原任务的extensions/独立目录，包含analysis.json、表格CSV及曲线PNG；继承原结果的科学验证状态。缺少数据需要明确报错或在预算内通过已有任务补数据，不能推测成功点。

## 审核与使用

1. `qpm_conventions(topic="extensions")`查询接口及可复制的signal-idler GVM示例。
2. `qpm_stage_extension`提交id、code、tests、metadata。metadata为kind、version、description、applicability；保存时只做AST语法检查。
3. 用户审阅后在设置中填写review_token。模型不能修改此设置。
4. `qpm_test_extension(token)`执行独立测试。测试须检查单位、符号、缺失数据与适用条件。
5. adapter用`qpm_adapt_task`后重新计划和提交；postprocess用`qpm_analyze_result(token,job_id)`，只能访问当前会话导出的结果。

示例文件位于examples/extensions/，它计算`(signal_beta1_ps_mm-idler_beta1_ps_mm)*1000`，输出有符号signal-idler GVM与有效采样点上的最大绝对值。它是不同于现有pump-signal GVM的新指标，使用已有β1数据而无需新求解。缺失点不插值，全部失败时指标为null、valid=false。

新令牌固定代码、测试与metadata；任意变更需重新审核和测试。旧adapter令牌仍兼容。已批准Python按可信本地代码执行，契约校验不是操作系统沙箱。禁止求解器调用、核心文件修改和改写源结果；新传播方向、材料/张量及求解模型安排独立开发验收。

## 模型验收
