# 使用说明

## 1. 你需要做的操作

1. 在Harness已有模型页面配置可用API与模型。插件不持有密钥。
2. 退出Harness，解压完整发布ZIP，在该目录执行README中的安装命令。默认安装到desktop profile。脚本会核对0.2.0-rc.2、备份包清单和用户配置。安装不会修改Harness安装文件或原虚拟环境。
3. 重新启动，插件设置中的「QPM设计助手」配置解释器、COMSOL、目录与预算。文本与数字失焦保存，其他字段逐项保存，采用官方持久化与版本冲突校验；正在运行的任务继续使用启动时快照。
4. 新建会话并选择「QPM 设计助手」预设。先运行演示任务，确认文件和图表。
5. 真实COMSOL试算前填写COMSOL程序路径、版本，开启「启用真实COMSOL」，再把默认后端设为comsol。明确仿真任务不需要每点确认。

0.2.0 内置原生 `qpm-design` Skill。助手先用 `skill` 加载规范；可直接输入“先加载 qpm-design，查询固定结构模板再规划”。旧会话可能继续保留旧预设内容，升级后应新建会话。规范查询 `qpm_conventions` 无需文件工具；`qpm_plan` 会解释晶轴、各波波长、默认值、预算和指标缺口。

本机解释器示例：`E:\work\Python\Comosol\Period\.venv\Scripts\python.exe`。Existing模式不会向它pip安装包；wheel解压到插件私有runtime/python-core。已有环境只读使用。Isolated模式独立安装，无需复制整个旧环境；依赖下载需要网络。正式分发时其他用户使用自己的解释器和COMSOL许可。

## 2. 参数优先级与术语

- 后端：demo为合成演示，comsol为真实求解，replay读取有校验的已有缓存；后者需任务提供replay_dir。
- 任务配置：LLM把自然语言转换为Python Task对象。用户明确的长度、扫描步长、公差优先于插件默认值。
- 预算：插件设置是上限，任务只能降低。默认32种搜索结构、1000次实际求解、1800秒、每会话2轮。全局同时只运行1项仿真。预算与数值成本由Python处理，不逐点调用LLM。辅助差分/公差扰动另产生求解次数，应看成本报告。
- 默认长度5mm，展示波长中心±50nm、20nm步长并加入中心。色散辅助点2nm、GVM基频±2nm/倍频±1nm、厚度导数±2nm。工艺公差独立设置。
- 工艺误差效率固定名义周期；周期误差表示重新匹配所需周期。效率为归一化效率及长度缩放过程系数；没有输入功率时不称实际转换百分比。
- LN/LT、x/z切、TE0/TM0、AIR/SIO2组合继承Python能力。非d33有效组合不会冒用d33输出效率；详见能力目录。

## 3. 可直接输入的任务

**固定结构与公差：**

> 先使用演示后端。在LN空气包层x切平台，薄膜厚600nm、刻蚀300nm、顶宽1800nm、TE0，设计1550到775nm的SHG。长度5mm，扫描1550±50nm，步长20nm并含中心；厚度公差±5nm、顶宽±10nm。输出周期、效率、β1、GVD、D及GVM曲线并解释公差结果。

**轻量结构搜索：**

> 使用demo，在同一结构平台搜索GVD最接近零的结构。厚度540到660nm、顶宽1500到2100nm，最大24种候选、最多8种追加、1000次求解，不要求全扫。只绘制最佳候选完整曲线，列出未覆盖范围。

**二维光谱：**

> demo后端，LT z切TM0、SiO2包层，厚600nm刻300nm顶宽1800nm。SPDC名义简并点775→1550nm，信号/闲频各扫1500到1600nm，先选5×5网格输出PMF热图。每格泵浦按能量守恒变化，采用名义点光栅；说明其不是固定泵浦二维实验，也不是绝对光子对产生率。

二维轴字段与过程定义可用capabilities/plan查看；机器可运行JSON例子随包提供examples/。设定二维任务必须给wavelength_axes_nm，以Python校验结果为准。

## 4. 结果与取消

工具只返回摘要和绝对文件路径；结果目录内有task.json、plan.json、result.json、report.md、曲线CSV、figures/、cache/、plugin-config.json及plugin-job.json。通过Harness文件访问能力或Windows资源管理器打开图表；初版未添加独立图表浏览器。任务由Harness后台任务服务显示，qpm_status读最终指标，qpm_cancel取消；插件卸载/退出清理自己拥有的进程范围，避免误停其他COMSOL实例。

会话销毁/重启后后台任务记录不恢复；已保存结果仍在磁盘。任务ID仅当前会话可访问，独立会话不能读取或取消他人的任务。结果复算需同一活跃会话任务ID；离线结果可用Python CLI postprocess。

## 5. 独立扩展确认

超出配置能力时，助手调用qpm_stage_extension保存extension.py、test_extension.py和manifest.json，仅作AST语法检查。用户审核代码与测试，确认来源与作用后，在设置的「人工审核令牌」填入工具给出的完整id:sha256（多个以空格分隔）。该字段不会由模型工具写入。

随后调用qpm_test_extension执行独立测试，支持无参数test_*函数和unittest.TestCase。adapter 通过后用qpm_adapt_task调用 `adapt_task(task:dict)->dict`，返回任务仍需计划校验与正常提交。postprocess 通过后用qpm_analyze_result(token,job_id)调用 `analyze_result(context:dict)->dict`，从当前会话结果计算新指标、表格和曲线，无需重新求解。

代码、测试或metadata变更使令牌失效。metadata需填写kind、version、description、applicability；省略时兼容旧adapter入口。扩展是人工审核后的可信本地Python代码，不提供操作系统沙箱，不支持自动替换求解器。测试依赖需在所选环境中已有，不向原环境安装。新分析写入任务目录extensions/，保留原结果及科学验证状态。完整接口与示例见[指标扩展说明](指标扩展.md)。

## 6. 排错与卸载

- 看不到预设：重启Harness，确认已安装bundle且package.json的dsh.profile.bundles含dsh-qpm-agent；安装脚本使用官方只读配置解析/合成接口校验；desktop不能通过CLI执行dump-config。
- 找不到模块：检查pythonModuleRoot指向wheel解压目录；Check-Qpm.ps1可读取installation.json自动检查。
- 缺少科学包：切换完整现有环境或使用Isolated模式。COMSOL许可状态不由只读环境检查推断。
- 已达轮数：开启新会话，或由用户在设置修改轮数。模型不能自行提高预算。
- 初次进入隔离Harness会要求API Key：配置页的可视验收需先完成这个Harness引导；本轮没有填写任何密钥。
- peer依赖警告：dsh SDK由桌面随附运行时提供，本机安装中pnpm给出peer warning，但CLI配置加载与原生SDK工具试算通过。不要盲目安装另一版SDK；其他版本未验证。
- 卸载：先退出Harness，执行Uninstall-Qpm.cmd。保留Python目录、结果、扩展和备份，不递归删除科学数据。若用户配置被Harness重写且保留了插件覆盖，请在配置编辑器清除qpm-runtime用户覆盖后重试；不要恢复整个旧配置覆盖后来新增的模型设置。

Windows推荐根目录Install-Qpm.cmd、Check-Qpm.cmd、Uninstall-Qpm.cmd和Repair-Qpm.cmd入口。它们只对子进程指定执行策略，避免默认Restricted拦截ps1；不修改永久策略。故障恢复命令优先用`Repair-Qpm.cmd -BackupDirectory ...`；错误中原ps1路径可通过`powershell.exe -NoProfile -ExecutionPolicy Bypass -File ...`启动。详见[Windows兼容性说明](Windows兼容性.md)。

手动安装：`E:\Deepseek Harness\resources\runtime\cli\bin\dsh.cmd plugin --profile desktop add <tgz绝对路径>`；安装wheel到独立环境或使用已有环境和私有包目录，重启后手动配置Python。手动卸载把add换为remove dsh-qpm-agent。

## 安装修正与失败恢复

Windows PowerShell 5.1和PowerShell 7共用逻辑，全部ps1为UTF-8 BOM，配置使用显式UTF-8读写。重装保留已有QPM配置；旧脚本在最后检查失败时留下的部分登记、缺少installation.json都可通过新安装脚本重试。包校验和不匹配会在修改profile前停止，请重新解压完整ZIP，不要手工改脚本后继续安装。

错误显示失败阶段、实际退出码和恢复状态；backups下operation.json保存脱敏诊断。自动恢复只处理本次QPM登记与未并发改写的配置，不盲目覆盖其他设置。配置发生并发修改时拒绝覆盖，关闭Harness后按错误中的Repair-Qpm.cmd命令恢复QPM部分。模型凭据文件不参与检查和备份。桌面实际加载、配置页和真实模型聊天仍需重启Harness后验收，安装静态成功不替代这些验证。
