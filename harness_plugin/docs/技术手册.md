# QPM Agent 中文技术手册

本手册面向首次安装和使用 QPM Agent 的研究者，也给维护者提供构建、验收和问题定位步骤。正式版本为插件 **0.3.0**；随包 Python Core 为 **0.1.0**。

## 1. 系统结构与能力边界

QPM Agent 由四部分组成：DeepSeek Harness 原生插件负责 Skill、工具和设置界面；插件的 Python worker 通过结构化 JSON 消息调用 Core；Core 读取任务配置并执行数值流程；COMSOL 作为用户本机可选求解后端。Harness 中的模型/API 负责把自然语言转成任务、选择工具和解释结果，参数物理校验、预算、数据处理和数值循环由 Python 代码执行。

建议交互顺序是：加载 `qpm-design` 规范 → 询问任务缺失信息 → 查询能力并生成计划/估算 → 用户检查计划 → 在预算内提交 → 查看状态/结果/诊断 → 必要时续算或绘图。任务超出已有能力时，助手应说明缺口；新指标可以通过审核后的后处理扩展实现，新材料张量、传播方向或求解方法需要独立开发和验证。

演示后端使用合成数据，适合验证工具流程，不是物理结果。真实后端只能在插件设置明确启用、Python桥接和COMSOL许可证可用时运行。模型不能通过工具提升插件设置中的预算上限。结果分析和图表不能替代独立科学验证。

## 2. 兼容与先决条件

### 已验证目标

- Windows 桌面 DeepSeek Harness **0.2.0-rc.2**。其他 Harness 版本、Linux、macOS 当前标记为未验证。
- Harness 随附 Node **24.18.1**、pnpm **11.7.0**；用户安装插件不需配置 Node。
- 64 位 Python **3.12.3** 验证；要求 Python 3.12+。
- COMSOL **6.4** 与 MPh **1.3.1** 是本机集成基线。其他版本须自行在隔离任务中验证。

### Python 依赖

基础功能需要 NumPy ≥2.0、SciPy ≥1.13、pandas ≥2.2、Matplotlib ≥3.8。Core wheel 随完整 ZIP 提供，但上述科学计算库由用户环境提供。真实 COMSOL 后端还需 MPh ≥1.3.1 和 JPype1 ≥1.5。建议使用 64 位 Python，并确保其 Java/COMSOL 连接方式与本机 COMSOL 安装匹配。COMSOL 自带 Java 环境时通常无需另装 JRE；若 MPh 无法连接，优先按 COMSOL/MPh 官方方式检查 Java 路径和进程位数。

### COMSOL 与授权

真实求解需要本机安装 COMSOL Multiphysics 和有效许可证。当前线性模式工作流依赖 Wave Optics / EWFD 及模式分析功能；具体模块授权取决于模型设置。插件和 GitHub Release 不包含 COMSOL 安装程序、许可证、模型 API Key 或用户已有模型文件。只读环境诊断不启动 COMSOL，也不代表许可证验证通过。

## 3. 准备专用 Python 环境

推荐建立专用环境，避免改变其他科研项目。以下 PowerShell 示例假设已安装 Python 3.12，并可访问 Python 包源：

```powershell
py -3.12 -m venv E:\work\Python\QPM-runtime\.venv
$py = 'E:\work\Python\QPM-runtime\.venv\Scripts\python.exe'
& $py -m pip install --upgrade pip
& $py -m pip install 'numpy>=2.0' 'scipy>=1.13' 'pandas>=2.2' 'matplotlib>=3.8'
# 真实 COMSOL 后端另装；纯 demo 可跳过此行
& $py -m pip install 'MPh>=1.3.1' 'JPype1>=1.5'
& $py -c 'import sys,numpy,scipy,pandas,matplotlib; print(sys.version); print(numpy.__version__,scipy.__version__,pandas.__version__,matplotlib.__version__)'
```

若 `py` 命令不可用，使用 Python 安装目录下的 `python.exe` 替代。Existing 安装方式只使用你指定的环境并把 Core wheel 解压到插件私有目录；它不会向该解释器执行 `pip install`。Isolated 方式由安装脚本创建独立环境，并通过网络安装 wheel 及依赖；网络受限时先用 Existing，或按内部包源配置 pip。

## 4. Windows 安装

### 安装前

1. 在 Harness 现有模型设置中配置 API 和模型；QPM 插件不保存密钥。
2. 退出 Harness，下载并解压 Release 中完整的 `QPM-Agent-0.3.0-Windows-Harness-0.2.0-rc.2.zip`，不要只复制 `.ps1`。
3. 确认 Python 环境依赖已安装，并验证 `python.exe` 路径。若开启真实后端，再准备 COMSOL 路径与许可证。
4. 可先使用 `Check-Qpm.cmd -PythonExecutable <python.exe>` 做只读依赖检查；未安装时优先使用你准备的解释器直接调用该命令。

### 推荐安装命令

在 ZIP 解压根目录运行 CMD 入口（引号不可省略）：

```powershell
.\Install-Qpm.cmd -PythonExecutable 'E:\work\Python\QPM-runtime\.venv\Scripts\python.exe' -PythonMode Existing
```

默认目标为 `desktop` profile。也可使用 `-PythonMode Isolated` 创建包目录内独立环境，但需要网络下载依赖。普通用户不需要管理员权限。CMD 入口调用 Windows PowerShell 子进程并指定临时执行策略，不修改系统持久 ExecutionPolicy；组织级 MachinePolicy/UserPolicy 仍由管理员策略控制。建议始终用 CMD 入口，而不是直接双击/调用 `.ps1`。

安装程序先校验 Harness 版本、发布文件 SHA256、Python 版本和依赖，再修改 profile。会备份 QPM 相关设置，并在安装后使用随附 Harness SDK 只读解析配置。静态校验成功表示插件登记与配置结构有效；桌面实际加载仍需重启 Harness 后确认。

### 首次启动

重启 Harness，打开插件设置卡片“QPM 设计助手”，检查 Python 路径、Core 私有包路径、COMSOL 路径/版本、结果目录和预算。创建新会话并选择“QPM 设计助手”预设；升级后旧对话可能仍持有旧 Skill 内容，推荐新建会话。第一次先保持默认 demo 后端。

## 5. 插件配置项

| 配置 | 作用与建议 |
|---|---|
| Python executable | 选第3节的 `python.exe`，需 Python 3.12+。 |
| Python module root | 通常由安装器写入插件私有 Core wheel 目录；手动安装时按安装包结构设置。 |
| Default backend | `demo`、`comsol` 或 `replay`。初次安装保持 `demo`。 |
| Enable COMSOL | 显式开关。关闭时即使任务请求 `comsol`，计划/执行也会拒绝。 |
| COMSOL binary/version | 指向 `comsol.exe` 或对应安装路径，并设置匹配版本；路径由设置管理，不能由任务绕过。 |
| Output root | 工作区结果根目录。建议使用本机有读写权限、非同步冲突目录。 |
| Extensions root | 保存待审核扩展；不要放入不可信共享目录。 |
| Length / wavelength step | 默认器件长度 5 mm、扫描步长 20 nm；用户明确值优先于一般默认。 |
| Dispersion stencil / step | 色散差分默认三点、间隔 2 nm；5/7点适用于用户明确要求或异常点复核。 |
| Tolerance | 厚度、顶宽默认不扰动；公差分析由任务显式给定。工艺公差和导数步长含义不同。 |
| Geometry / solver / time budgets | 插件端上限。模型任务可使用更低预算，不能提高设置上限。默认同时仅一个仿真任务。 |
| Auto resume / recovery attempts | 允许在预算范围内复用已保存点并恢复；恢复次数最多2。累计预算不会因续算重置。 |
| History sources | 登记历史结果目录供只读查询和绘图；插件不会扫描整个磁盘。 |
| Approved extensions | 人工审核令牌，仅在代码/测试/metadata哈希匹配时有效。不要让模型代替用户写入审批令牌。 |

正在运行的任务使用启动时配置快照；改设置只影响后续任务。

## 6. 环境诊断与开启 COMSOL

### 只读诊断

```powershell
.\Check-Qpm.cmd -PythonExecutable 'E:\work\Python\QPM-runtime\.venv\Scripts\python.exe'
```

也可在 Harness 调用 `qpm_environment`。输出报告 Python、模块导入和插件连接信息。它不启动求解器、不试许可证，也不会更改 Python 环境。

### 开启真实后端

1. 先在 COMSOL GUI 确认安装版本、模块许可证和模型可打开。
2. 在插件设置中填入 COMSOL 路径和版本，安装 MPh/JPype 到本次配置的 Python 环境。
3. 运行只读诊断，确认桥接模块可导入。
4. 将 `enableComsol` 打开、`defaultBackend` 改为 `comsol`，并确认输出目录可写、预算适合小规模试算。
5. 提交一项低成本、代表性任务。按需观察 Harness 后台任务状态、成本和日志；模式失败或预算暂停时先读诊断与已有结果，不要直接扩大任务规模。

真实 COMSOL 验收受本地许可证、网格、模型和版本影响。演示数据、配置检查、包安装测试不证明 COMSOL 科学结果。

## 7. 任务与工具流程

建议先要求助手“加载 qpm-design Skill，查询相关模板，生成计划与用时估算，不要提交”。常用工具顺序：

1. `qpm_conventions`：查晶向、几何、波长、指标、模板或绘图约定。
2. `qpm_capabilities`：读取实现范围、限制和当前验证状态。
3. `qpm_environment`：只读检查本机 Python 接入状态。
4. `qpm_plan` / `qpm_estimate`：标准化任务、列默认值/明确值/缺项/预算和估时。估算无历史数据时不应伪造精确用时。
5. `qpm_submit`：在已检查计划且获得自然语言任务授权后提交。返回后台 `job_id`。
6. Harness 后台任务或 `qpm_status`：查看进度、结果摘要和成本；`qpm_cancel` 可取消任务。
7. `qpm_result`、`qpm_runs`、`qpm_resume`、`qpm_study_*`：读取历史、续算或分阶段研究。只有实现支持的研究操作可执行，不能把研究规划当作自动完成的自主闭环。
8. `qpm_plot` / `qpm_plot_preset` / `qpm_postprocess`：重绘或比较历史结果，不重新求解且不扣仿真预算。

任务中的材料、晶切、传播方向、模式、包层、波长角色、几何和输出指标应尽可能明确。插件 Skill 与 `qpm_plan` 会说明默认值；对效率、SPDC绝对率或缺失的张量模型有疑问时，应要求助手列明假设，而不是默认把过程系数称作实际转换百分比。

## 8. 任务类型与结果

- **固定结构**：周期、效率/过程系数、β1、GVD/β2、D、GVM等目标曲线。默认加入扫描中心点，辅助差分点不必全部呈现在主扫描网格。
- **工艺公差**：对名义结构和公差端点实际计算，厚度/顶宽可做误差棒或包络；公差步长不等同于导数差分步长。
- **结构筛选**：依任务目标筛选结构，如 GVD/GVM 接近零或厚度敏感性较小。初扫+自适应追加受设计数、求解数、时长预算限制；最终候选需实算，不将代理预测作为结果。
- **SPDC PMF / SFG二维波长扫描**：按任务输出二维数据/热图。PMF 不等于绝对光子对产生率。
- **续算**：保存的点、缓存、任务设置和代码版本通过检查后只补缺失工作。累计预算保持不变，版本不兼容时报告原因。

完整结果通常包含 `task.json`、`plan.json`、`result.json`、报告、CSV、缓存、图表和逐点日志；文件结构由任务类型和版本决定。工具返回运行ID及实际路径。不要移动或修改仍需续算的缓存文件。

默认固定结构扫描为中心±50 nm、20 nm步长并加入中心；色散差分默认三点二阶，GVM和厚度导数使用配置中的小扰动。五点/七点差分不会对每个波长自动启用，避免不必要的求解成本。效率结果忽略损耗；没有输入泵浦功率时不应报告实际转换百分比。

## 9. 历史结果与绘图

`qpm_history_sources` 登记旧结果目录，`qpm_runs` 查询可用运行，`qpm_result` 读取摘要。已登记目录默认是只读输入；绘图输出进入当前工作区（或用户明确指定且有权限的目录）。跨目录、跨 run 曲线可以叠加、分子图、双轴或热图。不同采样波长保留各自原始点；插值、平滑或归一化必须由任务明确请求并记录。

`qpm_plot` 支持标题、图例、字体、颜色/线型、轴、刻度、坐标范围、误差棒/包络以及 PNG/SVG/PDF。绘图使用无界面后端和独立缓存目录，不启动COMSOL；读取和画图时间不属于求解预算。路径只允许插件策略授权的目录，操作系统权限仍适用；失败时工具应返回具体错误和建议路径。

## 10. 扩展能力

对已有求解能力，仅通过合法任务配置改变参数。新任务适配可实现 `adapt_task(task: dict) -> dict`；后处理扩展可实现 `analyze_result(context: dict) -> dict`。扩展必须提供代码、独立测试、版本、说明和适用范围，存入 Extensions root；插件做哈希和测试核验，用户审阅后才在设置中批准。启用后仍受任务校验、预算、数据单位和缺失点规则约束。

扩展执行属于用户审核后的本地可信 Python 代码，不是操作系统级隔离环境。不要批准不理解的源码，不允许其覆盖核心求解器。需要新的材料模型、晶体张量、传播方向或COMSOL建模方式时，应作为新物理能力单独开发和验收。

## 11. 故障排查、升级和卸载

| 现象 | 处理 |
|---|---|
| Windows 提示禁止执行 `.ps1` | 从解压根目录运行 `Install-Qpm.cmd`，不要直接调用 ps1。若组织策略拒绝子进程策略，联系设备管理员。 |
| 安装后预设不可见 | 重启 Harness；确认版本为 0.2.0-rc.2、插件静态校验通过，再查看 Harness 插件日志。安装静态验证不等同于 GUI 加载验收。 |
| Python版本或依赖失败 | 确认 64 位 Python 3.12+ 和科学包导入；检查安装时选用的解释器是否与设置页相同。 |
| COMSOL不可用/许可证失败 | 确认 COMSOL 路径、版本、MPh/JPype、Java连接和许可证模块；先从 COMSOL 应用本身验证许可。只读doctor不试许可证。 |
| 任务超时/求解预算耗尽 | 读取成本、失败原因和已完成点；使用 `qpm_resume` 时核对原 run 与累计预算。不要用新设计身份绕开预算。 |
| 历史结果找不到 | 先用 `qpm_history_sources` 登记原目录，再运行 `qpm_runs`；检查权限、文件是否完整及标识歧义。 |
| 图形中文乱码/写入失败 | 使用 `qpm_plot_environment` 查字体和路径；检查工作区权限、Matplotlib目录及长路径。不要修改历史结果目录权限作为默认处理。 |
| 配置校验失败 | 查看安装器给出的阶段、错误和恢复状态；安装备份位于解压目录 `backups/`。配置并发修改时关闭Harness后按错误提示执行 `Repair-Qpm.cmd`。 |

升级步骤：退出Harness → 备份用户输出 → 解压完整新版ZIP → 从新目录执行 `Install-Qpm.cmd` → 重启并环境检查。安装器只更新插件登记及其私有 Core 包并保留已配置的COMSOL、后端、预算等值。旧结果不会自动迁移或删除。

卸载前退出 Harness：

```powershell
.\Uninstall-Qpm.cmd
```

卸载只移除 QPM 插件登记，不删除用户结果、扩展、虚拟环境、备份或其他 Harness 配置。回退旧版时使用该版本完整安装包；保留当前数据副本，避免旧插件对新设置或结果格式作不兼容写入。不要整份恢复旧 profile 覆盖当前 API 或其他插件设置。

## 12. 开发构建与发行包验收

开发依赖为 Node 24+、Python 3.12+、Harness 0.2.0-rc.2随附SDK（提取到本机开发目录，不随包发布）、AUTO_Simulation Core源码和 pytest。设置路径后执行：

```powershell
$env:QPM_BUILD_NODE = 'C:\Path\To\Harness\resources\runtime\primary-runtime\dependencies\node\bin\node.exe'
$env:QPM_CORE_ROOT = (Resolve-Path '..').Path # Core源码在仓库根目录时
$env:QPM_TEST_PYTHON = 'C:\Apps\QPM\.venv\Scripts\python.exe'
python dev\release.py
```

`QPM_CORE_ROOT` 应指向含 `pyproject.toml`、`qpm_simulation/` 和 `tests/` 的 Core源码目录；若 Core 分开管理，替换为实际路径。完整入口依次生成任务契约、Windows CMD启动器、预编译插件、tgz、Core wheel、SHA256清单和Windows ZIP；运行 Python 与 Harness 插件测试、发布一致性检查，并从最终 ZIP 解压进行隔离 `desktop` profile 的 PowerShell 5.1/7安装回归。最终安装回执必须绑定 ZIP 的 SHA256。`--build-only`只做开发构建，不能当作已通过的安装验收。

Python Core 源码维护于 AUTO_Simulation；发布 ZIP将对应0.1.0 wheel作为插件运行依赖携带。插件安装ZIP不含 COMSOL、许可证、API 凭据、个人虚拟环境、测试profile或用户仿真结果。发布前应人工检查版本号、兼容表、变更记录、ZIP清单、PS脚本BOM、安装回执哈希和附件SHA256。不要上传本机配置、安装备份或数据结果。
