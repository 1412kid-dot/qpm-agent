# 三点差分、缓存与续算

## 使用示例

自然语言：保持厚度600 nm、刻蚀300 nm，扫描顶宽1200至1500 nm的四个合法点，在1500、1525、1550、1575、1600 nm计算信号TE0的GVD，只用三点2 nm差分。先给出采点与用时估计，查询已有缓存后执行。

任务设置：required_metrics=["gvd"]，dispersion_roles=["signal"]，dispersion_stencil_points=3，verify_numerics=false。单波段四结构五位置至多60个基础模式点（未计模式重试，重合点去重）。

仅1550 nm需五点检查：dispersion_refinement_wavelengths_nm=[1550]，沿用±2 nm，新增±4 nm。清单中不出现隐式九点。

三点先对neff(λ)计算一阶/二阶导数，再转换β1、β2与D；三点没有独立误差估计。五点检查保存三/五点差异，但不代表网格误差。求解失败或缺失点不插值成成功点。

## 中断与续算

1. 调用qpm_runs查看配置的结果目录中的run_id、状态及成本。
2. 明确继续原任务时调用qpm_resume(run_id)。它使用原任务设置，只补未完成点，不占设计迭代轮次；新的后台job_id由qpm_status查询。
3. 原预算已耗尽时先请用户允许增加累计总预算，再传budget；插件设置上限仍不可超过。
4. 修改结构范围、物理模型或差分规则时提交新任务，仍可复用物理身份一致的模式缓存；不改变旧任务的物理定义。

Python命令：python -m qpm_simulation resume "结果任务目录" --budget '{"max_wall_time_s":7200,"max_solver_calls":1000}'。CLI直接受任务预算控制，Harness还受设置页上限约束。

## 自动恢复边界

进程异常预算内最多恢复两次，不把模式筛选失败当成瞬时进程故障。用户取消不自动恢复。预算正常耗尽先保存报告，状态paused；硬超时先给协作退出机会，再结束该任务拥有的进程。已完成缓存不会删除，当前尚未落盘的点可能重算。

结果重启后可通过qpm_runs和qpm_resume找到；新的后台job_id仍受当前会话权限约束。原COMSOL项目、虚拟环境和API凭据不修改。

## 用时估计

依据必要模式点、合格缓存、相同材料/晶向/包层/模式/求解设置的历史耗时及重试比例估计。不同结构或首次建模可能偏离预测，输出范围而非承诺值。没有足够历史时返回未知。推荐值不会自动提高设置预算。搜索初筛与最佳候选曲线分别消耗预算，当前搜索估计明确保留未覆盖的后续成本说明。

## 验证状态

软件测试与演示不等于COMSOL科学验收。默认关闭额外网格和半步长复核；需明确请求verify_numerics=true才执行且计入预算。没有验收时，只报告当前最接近目标的结构，不宣称严格零点。
